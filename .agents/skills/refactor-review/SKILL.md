# Refactor Review Skill

이 스킬이 호출되면 다음 절차를 엄격하게 따르세요.

## 1. 사전 준비 (Context Gathering)
- 현재 작업 중인 프로젝트의 폴더 구조를 파악합니다.
- `project-rules.mdc` (또는 해당하는 프로젝트 컨벤션/규칙 파일)이 존재한다면 가장 먼저 읽고 숙지합니다.
- 사용자가 현재 열어둔(가장 활성화된) 소스코드 파일을 확인합니다.

## 2. 검토 목적 및 제약 사항
- **목적**: 기능의 변경 없이 코드의 구조와 가독성만 개선합니다.
- **제약 사항 (매우 중요)**:
  - 사용자의 명시적인 승인 전에는 절대로 파일을 직접 수정(Tool call)하지 마세요.
  - 전체 프로젝트의 아키텍처나 구조를 무리하게 변경하지 마세요.
  - 현재 파일 외에 다른 파일의 수정이 동반되어야 한다면, 그 이유를 먼저 사용자에게 설명해야 합니다.

## 3. 5대 검토 기준
해당 파일을 다음 5가지 기준으로 분석하세요:
1. 함수가 너무 많은 일을 하고 있는지 (단일 책임 원칙)
2. 중복 코드가 있는지 (DRY 원칙)
3. 변수명과 함수명이 그 역할을 명확히 설명하고 있는지
4. 예외 처리가 필요한 부분이 누락되었는지
5. 테스트하기 쉬운 구조인지 (의존성 주입 등)

## 4. 출력 형식
반드시 아래의 5가지 목차에 따라 마크다운 형식으로 마크다운 리포트를 작성하여 제안하세요.

1. **현재 코드 흐름 요약**
   - 현재 코드가 어떤 로직으로 동작하는지 간략히 설명
2. **리팩토링이 필요한 부분**
   - 위 5대 검토 기준에 부합하지 않아 개선이 필요한 영역
3. **수정 우선순위**
   - 어떤 부분을 가장 먼저 고쳐야 하는지 순서대로 나열
4. **어떤 함수로 분리하면 좋을지**
   - 구체적인 함수명과 분리될 역할의 제안
5. **수정하면 안 되는 부분**
   - 프로젝트 룰이나 현재 요구사항 상 유지되어야 하는 핵심 로직 또는 설정
